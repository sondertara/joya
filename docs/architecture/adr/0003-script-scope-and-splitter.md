# ADR-0003：`DataOps.script` 的定位与切分器

- 状态：Accepted（2026-11）
- 关联：评审 E-3 / R-M4；实现见 `SqlScriptSplitter`、`ScriptRunner`

## 背景

旧实现按行 `contains(";")` 切分：块注释里的分号、行尾注释里的分号、字符串里的分号、一行多语句都会切错；
且 `DEBUG` 级别会逐格打印 `SELECT` 结果集明文（敏感数据泄露）。评审给出两条路：A 轻量工具 + 标注限制；B 升级为完整状态机切分器。

## 决策

1. **定位保持 A**：`script` 是面向测试建表与简单初始化的**逃生舱**，不接观测、不保证原子性、不承诺生产库迁移能力（迁移用 Flyway / Liquibase）。
2. **切分器取 B 的最小实现**：复用内核既有的方言感知词法器（注释、`[]` 标识符、单/双/反引号、PG `E'...'`、`$$` 美元引号、`@DELIMITER`），先整体切分后执行，未闭合词法在**任何语句执行前**带行号失败。
3. 结果集日志降级为行/列摘要，不再打印单元格明文。

## 理由

- 状态机本身值得做：它是纯函数、零外部依赖、可单测，能消除「静默切错」这类高危害缺陷。
- 但把它包装成「生产级迁移执行器」是定位漂移：那意味着逐语句观测、事务包装、超时/deadline、`GO` / `/` 批分隔、流式大文件——与「轻量逃生舱」的契约冲突，且会与 Flyway/Liquibase 重复。

## 代价

- 整份脚本一次性读入内存；不支持超大转储文件流式执行与 SQL Server `GO` / Oracle `/`。
- 自动提交模式下前序语句不会因后序失败回滚（文档已明确）。
- 词法边界随方言而异：MySQL 家族（及方言未知的通用模式）要求 `--` 后紧跟空白或控制字符才算行注释（`SET x = x--1` 中的 `--1` 是算术），标准方言（PostgreSQL / H2 等）则任意位置的 `--` 都是注释。
- `@DELIMITER` 切换后的分隔符按字面量子串、区分大小写匹配（与历史 `ScriptRunner` 一致）：`GO` 这类单词分隔符须与脚本体大小写一致，标识符若含该子串会被提前切分。
